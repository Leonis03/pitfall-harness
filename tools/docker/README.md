# Docker 基础指南：容器隔离与常用命令

---

## 一、Docker 解决什么问题

在一台电脑上能跑的程序，换到另一台电脑上常常报错：Python 版本、依赖库、环境变量、驱动只要有一项对不上，程序就起不来。

Docker 把程序连同它运行所需的**系统环境、依赖库和配置文件**一起打包成一个容器。只要装了 Docker，在任何机器上都能用同样的环境运行它，容器内的环境不受宿主机上其他软件影响。

```
┌──────────────────────────────────────────────────────────┐
│                      物理电脑 / WSL                      │
│                                                          │
│   ┌─────────────────────┐      ┌─────────────────────┐   │
│   │   容器 A (Python)    │      │   容器 B (NodeJS)   │   │
│   │ ┌─────────────────┐ │      │ ┌─────────────────┐ │   │
│   │ │ 独立文件系统    │ │      │ │ 独立文件系统    │ │   │
│   │ │ 自己的软件环境  │ │      │ │ 自己的软件环境  │ │   │
│   │ └─────────────────┘ │      │ └─────────────────┘ │   │
│   └─────────────────────┘      └─────────────────────┘   │
└──────────────────────────────────────────────────────────┘
```

## 二、三个核心概念

| 概念     | 英文名                    | 作用                                                         |
| :------- | :------------------------ | :----------------------------------------------------------- |
| **镜像** | **Image**                 | 静态模板，**只读**，包含运行某个软件所需的全部文件。         |
| **容器** | **Container**             | 镜像运行起来的实例。可以进入它、在里面写代码、删除它。       |
| **仓库** | **Registry / Docker Hub** | 存放和分享镜像的地方，用 `docker pull` 下载。                |

关系：从仓库下载镜像，用镜像启动容器。

## 三、为什么运行 AI Agent 时适合用 Docker

让 AI Agent 自主执行命令时，常见的担心是它误删文件，或者把电脑环境改坏。

* **隔离**：容器有独立的文件系统，Agent 在容器内的操作不会直接作用到宿主机。
* **可重建**：即使 Agent 在容器内执行了 `sudo rm -rf /*`，损坏的也只是这个容器。删掉它，重新 `docker run` 一个即可，通常几秒钟。
* **边界**：隔离只覆盖容器自己的文件系统。用 `-v` 挂载进容器的宿主机目录是可读写的，Agent 在里面做的修改会保留（见第六节）。

## 四、在本机使用 Docker

本机（WSL Ubuntu）上的 Docker 已安装并配置好，作为后台服务开机自启，可以直接使用。

### 场景 1：临时隔离沙盒

```bash
# 启动临时 Ubuntu 容器并进入交互终端（--rm：退出时自动销毁）
docker run -it --rm ubuntu:26.04 bash
```
> 进入后提示符变成类似 `root@a1b2c3d4e5f6:/#`，这是一个全新的 Ubuntu 环境。在里面执行的任何操作，输入 `exit` 退出后都随容器一起销毁。

---

### 场景 2：给 AI Agent 一个专属工作目录

让 Agent 处理某个项目，又不想让它接触其他文件时，用 `-v` 只把指定目录挂载进容器：

```bash
# 1. 在本地创建沙盒目录
mkdir -p $HOME/code/docker/sandbox

# 2. 启动容器，只把该目录挂载到容器的 /app
docker run -it -v $HOME/code/docker/sandbox:/app ubuntu:26.04 bash
```
* **效果**：容器内只能访问 `/app` 里的文件，宿主机上的其他磁盘和用户主目录在容器内不可见。

---

### 场景 3：运行现成的服务

* **纯净的 Python 环境**：
  ```bash
  docker run -it --rm python:3.12-slim python
  ```
* **后台运行 Nginx**：
  ```bash
  docker run -d -p 8080:80 --name my-web nginx
  ```
  *(启动后在 Windows 浏览器打开 `http://localhost:8080`)*

## 五、常用命令速查

| 想做什么                         | 命令                       | 说明                           |
| :------------------------------- | :------------------------- | :----------------------------- |
| **查看运行中的容器**             | `docker ps`                | 列出正在运行的容器             |
| **查看所有容器（含已停止）**     | `docker ps -a`             | 列出全部容器记录               |
| **查看本地镜像**                 | `docker images`            | 列出本地保存的镜像             |
| **停止容器**                     | `docker stop <容器名或ID>` | 正常停止容器                   |
| **删除已停止的容器**             | `docker rm <容器名或ID>`   | 释放空间                       |
| **删除镜像**                     | `docker rmi <镜像名>`      | 删除不再使用的镜像             |
| **清理无用的容器、网络和缓存**   | `docker system prune -f`   | 释放被废弃对象占用的磁盘       |

## 六、注意事项

1. **确认命令在哪里执行**：
   * 通过 `docker run`、`docker exec` 进入容器后输入的命令，才是在容器里运行。
   * 直接在 WSL 终端输入的命令，作用在宿主机系统上。
2. **谨慎挂载宿主机目录**：
   * 不要把宿主机根目录 `/` 或 Windows 盘符 `/mnt/c` 挂载给不可信的脚本或 Agent（避免 `-v /:/host`、`-v /mnt/c:/c`）。
   * 最小权限原则：需要哪个目录，就只挂载哪个目录。
